# FinDashboard Web 设计规范

本规范定义 Web 工作台与桌面研究控制台共用的视觉语言。2026-11-27 经 #562 确认的双主题是后续页面改造的目标。已发布 Web 的当前取值见 [主题实现](src/index.css)。

## 1. 页面内容与信息密度

先写清楚用户在本页要判断什么、可以执行什么，以及哪些条件会阻塞操作。首屏给出完成该任务所需的状态、数据和下一步。字段、指标、操作、模块数量和排列顺序由该页实际功能、权限和数据契约决定。

- **留在首屏**。当前对象和范围、影响当前决策的结果或异常、主要操作。研究运行的执行状态和样本外结论各有独立含义。涉及实盘的区域标识、危险操作的影响和确认要求应在操作当下可见。
- **就地展开**。一行摘要足以支持判断，明细只用于追查时，展开该行。例如点击受限的数据源，直接看到受影响的接口和原因。展开控件显示状态，键盘可操作。
- **进入下一级**。需要单独筛选、比较、分页或引用的内容，采用具名页签或详情页。例如查看某年的表现、核对冻结输入或排查某段耗时。返回时保留原对象与浏览位置。
- **按任务调密度**。研究数据表可从 12px 字号、26px 桌面行高起步，数值按列对齐，标明单位和窗口。窄屏优先保留任务所需列，其余可通过表格内横向滚动或详情查看。交互目标遵循 §7。

[蓝色双主题 HTML 参考稿](../docs/design/blue-workbench.html) 可离线打开，供对照明暗外观、选中反馈和明细展开。两屏中的导航、四项指标、文案和示例数据只是对应场景的一种演示。开发验收以具体页面的功能与数据契约为准。

## 2. 双主题与品牌色

近黑与纯白作为工作底色，大部分表面、文字与分隔线用中性色。饱和蓝集中用于字标图形、主要操作、键盘焦点和需要强调的图表系列。以下是目标 sRGB 色值。Web 将色值转换为既有 HSL token，组件通过语义 token 取色。

| 角色 | 深色 | 浅色 | 用法 |
|---|---|---|---|
| 页面底色 | `#020303` | `#FFFFFF` | `--background` |
| 内容面板 | `#0A0B0C` | `#FFFFFF` | `--card`，浅色靠分隔线组织表面 |
| 正文 | `#FBFCFD` | `#080A0C` | `--foreground` |
| 辅助文字 | `#969DA3` | `#545D65` | `--muted-foreground`，列头、单位与时间 |
| 次级表面 / 悬停 | `#17191C` | `#F2F3F4` | 表头、工具区与可交互项 |
| 选中表面 | `#1C2025` | `#E8ECEF` | `--accent`，整项中性底 |
| 分隔线 / 控件边界 | `#303337` / `#53585D` | `#C9CED2` / `#8F969D` | `--border` / `--input` |
| 主操作 / 焦点 | `#008CFF` | `#0064FF` | `--primary` / `--ring` |
| 主按钮文字 | `#02090E` | `#FFFFFF` | `--primary-foreground`，与本列主色成对使用 |

字标使用 **FinDashboard**，三根递增柱可作独立小图标，随主题使用品牌蓝。在 16px 尺寸检查三柱之间仍可分辨。主题沿用 Web 的 `:root` 深色、`.light` 浅色及 `findashboard-theme` 存储键，首帧恢复用户选择。

## 3. 形状与交互状态

- **微圆角**。面板、弹层、按钮、输入框和选中底块取 2px，紧凑标签取 1px，表格内部格线保持直角。圆点、单选和开关保留各自的几何形状。Web 实施时分别映射 `rounded-lg/md/sm` 的目标值，避免沿用旧版半径减法得到负值。
- **表面**。用细中性描边、底色和间距分组。弹层使用独立表面色与边框，保持无阴影。静态面板保持稳定，仅可交互元素提供悬停反馈。
- **当前位置**。导航和页签选中时使用整项中性底色、较高字重和清楚的文字。带图标的导航可将当前图标点蓝。侧边色条和页签底部彩线由整项选中态替代。
- **操作与焦点**。突出当前任务的主要操作，次级操作用中性按钮或工具栏图标。键盘焦点使用 2px 蓝色外环，与持续选中态分别表达。使用适配控件的 `aria-current`、`aria-selected`、`aria-pressed` 或 `aria-expanded`。
- **图形**。策略与基准同图时，可用品牌蓝实线和中性虚线配文字图例。图表系列通过图表 token 取色。关键状态以文字和可区分的图形表达，正常状态可用小勾或就绪点，需处理的异常给出具名原因与可达入口。

## 4. 字体与图标

- 中文正文和控件优先使用操作系统无衬线字体。Windows 使用 Microsoft YaHei UI / Microsoft YaHei，macOS 使用 PingFang SC，Linux 使用本机可用的 Noto Sans CJK SC，最后回退到 `system-ui, sans-serif`。表单、页签和标签继承界面字体。
- 可比较的数字使用 `tabular-nums`，按列右对齐。运行 ID、校验和、时间戳与日志可使用 Cascadia Mono / Consolas / SFMono-Regular / Menlo。数值单元格的对齐与字体分别控制，使「2 分钟前」等混排内容保留中文界面字形。
- 使用项目已有的 Lucide 线性图标。桌面导航图标约 16px，紧凑按钮内约 14px，统一线宽。可见短标签说明操作，仅图标的按钮提供可访问名称和提示，图标大小与可点击范围分别设置。

## 5. 语义色与 A 股惯例

| 用途 | 深色前景 | 浅色前景 | 辅助识别 |
|---|---|---|---|
| 涨 / 跌 | `#FF777B` / `#47C898` | `#BA2938` / `#087447` | `up/down` 配合正负号或涨跌文字 |
| 正常 / 已完成 | `#69C39D` | `#176E4B` | `success` 配小勾或就绪点和状态名 |
| 警告 / 待处理 | `#FFC454` | `#825708` | 警告图标与原因，提示底色分别为 `#262016` / `#FFEFCA` |
| 错误 | `#FF9A72` | `#9F421D` | 错误图标、具名原因和可执行的恢复动作 |

收益与运行状态使用各自的语义 token。表格中常规状态使用中性文字与小图标，交易风险或需要处理的异常可使用有色提示底。带底色的控件需同时指定并验证前景色。信息提示使用 `info`，系列颜色使用 `chart-1..8`，键盘焦点使用 `ring`。

## 6. 共享组件契约

- 页面容器统一 `PageHeader`(唯一 `h1`，按页面任务提供说明和操作)与
  `PageContainer`(max-w-7xl 居中)。
- 表格统一 `Table` 组件(自带 `overflow-x-auto` 横向滚动);
  行级操作不用整行点击,交互元素必须是真实按钮。
- 状态展示统一 `States` 组件:`EmptyState / LoadingState / ErrorState(onRetry)
  / BlockedState`;动态结果用 `role="status"` / live region。
- 表单控件必须有可见 `Label` 或 `aria-label`;placeholder 只作示例。
- 按钮尺寸:`Button` 默认 h-9;触控目标规则见 §7。

## 7. 触控目标与键盘

- 交互元素可点击外框 **≥ 44px** 优先(移动端)。图标按钮
  (`size="icon"`)用 `h-11 w-11`(44px);提示入口(InfoHint 等)加
  `p-2` 保证命中区。
- **登记例外**:桌面端高密度表格工具栏的紧凑按钮(`size="sm"`,约 32px)
  与行内内联按钮允许缩小,但必须带可见文字或 `aria-label`,且按钮间距
  ≥ 8px;移动端断点下恢复 44px 或改用图标按钮。
- 可点击 div/tr 必须改为 `button` / `a` 等语义元素:支持 Enter/Space、
  可见焦点(ring)、`aria-expanded` 等状态属性。

## 8. 可访问性基线

- 明暗两版分别检查实际相邻的前景与背景。正文、次要文字和状态文字按 WCAG AA 普通文本至少 4.5∶1 验收。参考稿的主按钮文字在深色蓝底上约为 5.91∶1，在浅色蓝底上约为 4.92∶1。
- 状态播报:错误/成功反馈用 `Alert`(自带 `role="alert"`)或
  `aria-live="polite"`;避免只靠颜色传达。
- 页面唯一语义标题:AppShell 顶栏**不渲染** `h1`,页面内容区每个路由
  有且只有一个 `h1`(由 PageHeader 提供)。

## 9. 数据刷新策略

- React Query **默认不轮询**(`refetchInterval` 为查询级 opt-in)。
- 需要实时性的查询(账户/持仓/订单/成交/任务中心)显式声明
  `refetchInterval`;静态研究查询(列表/报告/因子)不轮询。
- 任务类查询在存在非终态任务时轮询,全部终态后自动停止
  (参考 `/jobs` 任务中心页的 `refetchInterval` 函数式写法)。

## 10. 页面使用示例

- 列表页(任务中心 `/jobs`):`PageHeader` + 筛选区(`Label`+`Select`)+
  `Table`(状态徽章 `StatusBadge`,进度 `Progress`)+ `States` + 轮询
  函数式 `refetchInterval`。
- 图表(回测权益曲线 / 组合饼图):recharts 的 `stroke/fill/contentStyle`
  一律用 `hsl(var(--x))` 形式引用 token,禁止 hex 字面量。

## 11. 回滚

本规范只约束前端展示与交互;回退方式为回退 token/组件提交,不涉及
数据库迁移或研究/实盘数据。
